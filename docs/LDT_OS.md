# Long-Distance Travel — Out-of-State (Visitor)

The LDT model is a **national, activity-based long-distance travel model**. It
simulates long trips (roughly 50+ miles one way) for the U.S. population using a
**joint destination- and mode-choice** model at its core. In TSM it is run in two
parts — FL residents and **Out-of-State (OS) visitors entering Florida** — and this
dialog runs the **OS** part.

Each household's long-distance travel is built as a cascade of discrete-choice
(logit) models. Tours are generated by purpose, then sized, scheduled, sent to a
destination by a chosen main mode, and assigned a vehicle.

---

## How a long-distance tour is built (the steps)

The models run in sequence; each one conditions the next.

1. **Auto Ownership** — number of vehicles the household has (0–4). Sets the
   vehicle context for later mode and vehicle choices.
2. **Tour Frequency & Purpose** (tour generation) — how many long-distance tours
   the household makes, by **purpose**: personal business, visit friends/relatives,
   leisure, commute, and employer business. A nested logit ties frequency to the
   accessibility of each purpose.
3. **Nights Away** (duration) — the length of each tour: daytrip, 1–2, 3–6, or 7+
   nights. Duration shapes party size, destination range, and mode.
4. **Party Size** — how many people travel together on the tour: 1, 2, 3, or 4+.
5. **Destination Zone + Main Mode** — the **joint** choice at the heart of the
   model: the tour's destination zone **and** its main mode (**car, bus, rail,
   air**) are chosen together, so the attractiveness of a destination depends on
   how well it can be reached by each mode (and vice-versa), using the Air/Rail/Road
   level-of-service skims.
6. **Vehicle Type & Allocation** — for car tours, which household vehicle type is
   used (affects operating cost, and downstream toll/VOT).

The result is a list of tours (and their outbound/return trip legs) by purpose,
party size, duration, destination, and mode — the long-distance demand that feeds
the trip table and assignment.

## Skims & inputs (and a future note)

The OS model is driven by the **US synthetic households** and the **Air, Rail, and
Road level-of-service skims**, which are **pre-generated outside TSM** (US land use
in 5-year increments → US household synthesis; US-wide multimodal skims). They are
not rebuilt per scenario — reuse the maintained set unless a scenario specifically
tests tourism indicators (check with the TSM team first).

## External station scaling (the table)

Future-year external volumes are **actually modeled** — the OS LDT generates the
trips into FL from the US synthetic population and skims, so external traffic
responds to land use and network changes on its own.

The **external station table** is an optional **overwrite**: it pins the
long-distance trips entering/leaving FL at the three Interstate gateways to
specified targets. Each row is a gateway with:

- **Ext Zone ID** — the external zone the gateway loads into.
- **Base Count (2024)** — observed base-year crossing volume.
- **Future Target or Growth %** — an absolute future-year target, or a growth rate
  (ending in `%`) applied to the base count.

Use this **only in rare cases** — analyst judgment, historical growth, or a
project-specific scenario. Left at the modeled values, no overwrite is applied.

| Gateway | typical corridor |
|---|---|
| **I-75** | NW Florida ↔ Georgia |
| **I-10** | Panhandle ↔ Alabama / west |
| **I-95** | NE Florida ↔ Georgia / east coast |

## Configuration file

When you click **Run**, the dialog writes the LDT control file the engine reads —
`<scenario>/LDT_visitor.txt` (same `KEY value` format as `LDT_OS_config.txt`). The
fields you set on the left are written into it:

| GUI field | Control key |
|---|---|
| Input Directory | `InputDirectoryName` |
| Road / Rail / Air LOS (OMX) | `RoadLOSFileName` / `RailLOSFileName` / `AirLOSFileName` |
| Land-use (FL) | `ZoneLandUseFileName` |
| Syn HH (FL/US) | `HouseholdFileName` |
| Num of HHs | `numberOfHouseholds` |
| Output Dir | `OutputDirectoryName` |

The coefficient files and model constants come from `config/ldt_coefficients`
(`CoefficientDirectoryName`); they are fixed by the model and not edited here.

The external-station table is written separately to
`<scenario>/ldt_external_targets.csv` for the downstream external-overwrite step.
