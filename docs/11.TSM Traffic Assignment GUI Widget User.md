# TSM Traffic Assignment GUI Widget User Guide

## Introduction
The Traffic Assignment widget within the Turnpike State Model (TSM) performs essential tasks for assigning traffic flows on network links using specified trip tables and network layers. It runs the **ELToD** (Express Lanes Time of Day) quasi-DTA assignment, and provides functionalities such as Select Link Analysis, Select Trip Tables, Subarea Trip Table Extraction, and Turning Movement Analysis.

---

## How ELToD assigns traffic — semi-static (quasi-DTA)

ELToD is a **semi-static, quasi-dynamic** assignment: more than a single static
assignment, but not a true dynamic traffic assignment (DTA) like HyDRA (AgentFlow-DTA).

**What makes it quasi-dynamic.** ELToD slices the day into **time-of-day intervals**
— hourly statewide, or **15 / 30 min** for corridor-level work — and loads each
interval's trips separately. After each interval it **recomputes congested link
travel times and re-routes** (recomputes paths) for the next interval, so the
assignment follows the time-of-day build-up and decay of demand and carries those
travel times forward. That feedback is what makes it *more* than a static run.

**Why it is still "semi-static" (not dynamic).** Each interval is solved on its own:
link travel time is a **stateless BPR / VDF** function of *only that interval's*
volume versus capacity. There is **no state carried between intervals** — no residual
queue or delay left over from the previous interval, and **no spillback / upstream
blockage**. An interval knows nothing about congestion that did not clear in the
interval before it.

**Planning-level delay added at the link.** On top of BPR, two link-level penalties
add realism without making the model dynamic:

- **Freeway ramp / interstate delay** — ramp queues backing into the mainline are
  approximated as a **link-level penalty**, applied when the link is **shorter than
  2 miles**.
- **Arterial signal delay** — the **number of signals on each (consolidated) link**
  is counted during link consolidation and stored on the link. A **planning-level
  signal-delay model** then applies delay as a function of **link volume / planning
  capacity**. These relationships were estimated from **HERE data** (signal density;
  free-flow → congested travel time by hourly volume).

> **Not the same as HyDRA.** This planning-level signal delay is a static,
> volume-based link penalty. It is **not** the signal / junction-delay model in
> HyDRA's micro simulation, nor HyDRA's car-following (**IDM**) and lane-change
> (**MOBIL**) freeway dynamics. HyDRA resolves delay and queues from the actual
> movement of individual agents between time steps; ELToD approximates them per
> interval from volume and capacity, with no memory across intervals.

## GUI Overview

### Input Configuration

#### 1. **TSM Link Layer**
- **Description:** Network link layer (LineString geometry).
- **Interaction:** Select the appropriate link layer from the dropdown.

#### 2. **TSM Node Layer**
- **Description:** Network node layer (Point geometry).
- **Interaction:** Choose the correct node layer from the dropdown.

#### 3. **TSM Trip Table**
- **Description:** CSV file containing origin-destination trip data.
- **Interaction:** Click **Browse** to select the trip table.

#### 4. **Output Volume File**
- **Description:** File for saving traffic assignment results.
- **Interaction:** Click **Browse** to specify an output file.

#### 5. **Max Iterations**
- **Description:** Maximum number of iterations for traffic assignment convergence.
- **Interaction:** Enter a numerical value (default is 10).

---

### Analysis Tools

#### 1. **Select Link Analysis**
- **Description:** Filters assignment results based on specific links.
- **Interaction:**
  - Specify Select Links (Link A-B).
  - Choose logical conditions (AND, OR, or single Select Link).
  - Set output directory for the Select Link results.

#### 2. **Select Trip Table**
- **Description:** Extracts specific trip tables based on Select Link criteria.
- **Interaction:**
  - Define Select Links.
  - Choose logical conditions (AND, OR).
  - Specify output directory for the resulting trip table.

#### 3. **Subarea Trip Table Extraction**
- **Description:** Extracts trip tables for a defined subarea.
- **Interaction:**
  - Specify boundary link list file.
  - Enter the number of subarea zones.
  - Define the output file for the subarea trip table.

#### 4. **Turning Movement Analysis**
- **Description:** Analyzes traffic turning movements at specified nodes.
- **Interaction:**
  - Provide a node list file.
  - Specify the output directory for turning movement data.

---

## Execution and Saving

- Click **Run** to execute the traffic assignment process.
- Click **Save** to retain configuration settings for future runs.
- Click **Cancel** to discard unsaved changes and exit.
